# Design

## Context

See proposal.md for why. Requirements are in `specs/design-tokens/spec.md`.

`index.html` links `src/base.css`, which sets `color: CanvasText` and `background: Canvas` on `body`. There is no `src/core/theme` and no `src/app/theme`. `App` renders an `h1` whose text is Signalfire. `pnpm dev` is `vite`. `pnpm build` is `vite build`. `pnpm lint` is `biome check`, then `node tools/layer-boundaries/check-fixtures.mjs`. `pnpm check` runs typecheck, lint, test, and build in that order. CI's Lint job runs `pnpm lint`. The production document is served with `style-src 'self'`. Vite's production build emits CSS as a file under `/assets/`.

`src/core` may import only itself and Zod. Node 26.11.1 runs erasable TypeScript by type stripping ([Node.js TypeScript modules](https://nodejs.org/docs/latest/api/typescript.html)). Tools in this repo are `.mjs` files outside `tsconfig.json`.

## Goals / Non-Goals

**Goals:**

- One constants module whose hex values are the design-system tables, plus integers a renderer can read.
- A generator that turns that module into OKLCH CSS, including the zone rules and the `@theme inline` map Tailwind v4 needs.
- `pnpm dev` and `pnpm build` refresh that CSS. `pnpm lint` fails when the committed file differs.
- The served page paints `#0B1026` and `#E6EAF5`. The heading stays Signalfire.

**Non-Goals:**

- Loading font files, installing shadcn, Ladle, lucide-react, or Motion.
- Painting glass, focus, or finger colors on the empty page. Those values exist as constants and CSS variables.
- Adding the Tailwind plugin to `vitest.config.ts`. The browser smoke does not import theme CSS. End-to-end uses the production build.

## Decisions

### Tailwind v4 is the styling setup in this change

Horizontal 07's pipeline ends in CSS variables mapped with `@theme inline` for Tailwind. Horizontal 03 names Tailwind CSS v4 for React UI. The Vite integration is the official plugin: dev dependencies `tailwindcss` and `@tailwindcss/vite`, registered in `vite.config.ts` next to the React plugin. No PostCSS config and no `tailwind.config.ts`.

`src/app/theme/app.css` is the entry `src/main.tsx` imports:

```css
@import "tailwindcss";
@import "./tokens.css";

html {
	background: var(--background);
	color: var(--foreground);
}
```

The page color uses the variables, so it does not depend on a utility class. `@theme inline` is still generated so later utilities (`bg-background`, `text-foreground`) follow the same variables. [Tailwind theme variables](https://tailwindcss.com/docs/theme): `inline` makes a utility use `var(--background)` rather than a second variable that would ignore `data-zone`.

Pin exact versions, the same way the existing devDependencies are pinned. Confirm both packages resolve. Do not add them to `dependencies`.

Alternative: plain CSS variables and no Tailwind until shadcn. Rejected. The pipeline's output is the `@theme inline` map, and a later install would have to redo it.

### Constants stay in core; conversion stays in the generator

`src/core/theme/tokens.ts` exports one `tokens` object. It imports nothing. No enums. Hex strings match the spec, uppercase, as `#0B1026`. Each hex color also has `int`, the integer for that hex (`0x0b1026` for background). Card keeps `alpha: 0.72` beside its opaque integer. Accent and ring are `{ source: "zone" }`, not a hex. `text-active` is `#FFFFFF` with `glow: "sm"`. `static` is the flat `#9CA3AF`. Zone 9's accent is the unrestored `#9CA3AF`. Zone 5 is the only zone with `accent2: "#FB7185"`. Zone ids are `"0"` through `"9"`. Store each zone's name from the design-system table on the same object.

`tools/tokens/generate.mjs` imports that module:

```js
import { tokens } from "../../src/core/theme/tokens.ts";
```

The `.ts` suffix is required by Node's type stripping. The file stays outside `tsconfig.json`, like the other tools. `culori` is imported only here. `core` does not import it, so the client bundle does not include it.

Before adding `culori`, read its license. Stop if it is not MIT, Apache-2.0, BSD, or ISC.

OKLCH serialization, so the bytes stay stable:

- Convert with `culori`'s `converter("oklch")`.
- Write `oklch(L C H)` using culori's 0–1 lightness, not a percentage.
- Round L, C, and H to 5 digits after the decimal. Normalize H into `[0, 360)`.
- When the token's alpha is not 1, append ` / N%` using the token's own percent (72, 60, 40, 45, 50). Do not run alpha through the 5-digit rounding.
- The file is UTF-8, ends with one newline, and starts with the comment `/* Generated by pnpm tokens. Do not edit. */`. No date and no package version in the file.

Alternative: store OKLCH in `tokens.ts` and skip `culori`. Rejected. Horizontal 07 keeps hex as the readable source and puts OKLCH in the generated CSS. A hand-rolled converter is easy to get wrong, and the check would then lock the mistake in.

### Generated CSS shape

`src/app/theme/tokens.css` holds two parts.

`:root` and `[data-zone]` are ordinary CSS. `:root` defaults `--zone-bg` and `--zone-accent` to zone 0, and sets `--accent` and `--ring` to `var(--zone-accent)`. Each `[data-zone="0"]` through `[data-zone="9"]` sets that zone's pair from the constants. `[data-zone="5"]` also sets `--zone-accent-2`. Fixed colors (`--background`, `--card`, finger colors, meaning colors, and the rest) live on `:root` as OKLCH.

`@theme inline` maps those variables into Tailwind namespaces, each utility pointing at the variable:

| Namespace | Examples |
|---|---|
| `--color-*` | `--color-background: var(--background)`, `--color-accent: var(--accent)`, `--color-finger-l-pinky: var(--finger-l-pinky)` |
| `--font-*` | `--font-mono`, `--font-display`, `--font-ui` |
| `--text-*` | `--text-type-target: 40px` and `--text-type-target--line-height: 48px`, and the same for the other steps |
| `--radius-*` | `--radius-lg: var(--radius)` |
| `--shadow-*` | `--shadow-glow-sm`, `--shadow-glow-md`, `--shadow-glow-lg`, `--shadow-focus` |
| `--ease-*` | `--ease-micro: ease-out`, `--ease-scene: cubic-bezier(1, 0, 0, 1)` |

`:root` also sets `--radius: 14px`. `rounded-lg` becomes 14px. The other Tailwind radius steps stay the defaults until shadcn.

Glow shadows use the current accent:

```css
--shadow-glow-sm: 0 0 8px color-mix(in oklch, var(--accent) 40%, transparent);
```

`glow-md` is 18px at 45%. `glow-lg` is 36px at 50%. `--shadow-focus` is `0 0 0 2px var(--ring), var(--shadow-glow-sm)` expressed so the 2px ring and `glow-sm` are both present. Glass is not a shadow utility: `--glass-blur: 16px`, `--glass-border-width: 1px`, and a border color that is `color-mix(in oklch, var(--border) 60%, transparent)`. Do not map glass blur to `--blur-*`. That namespace is `filter: blur()`, and glass is a backdrop blur.

Font families include a generic fallback so a missing file still renders: `"Atkinson Hyperlegible Mono", ui-monospace, monospace`, `"Space Grotesk", ui-sans-serif, sans-serif`, and `"Inter", ui-sans-serif, sans-serif`. Do not replace Tailwind's `--font-sans`. Do not set `font-family` on `html` or `body`. Preflight may change the heading's margin; it must not switch the page to Inter.

Motion durations are plain variables, because Tailwind has no duration namespace: `--motion-micro-duration: 100ms`, `--motion-standard-duration: 240ms`, `--motion-standard-stiffness: 380`, `--motion-standard-damping: 30`, `--motion-scene-duration: 650ms`, `--motion-celebrate-min: 1.2s`, `--motion-celebrate-max: 2s`. The scene bezier is [easings.net easeInOutExpo](https://easings.net/#easeInOutExpo). There is no CSS stand-in for the spring.

Stacking and icons are plain variables: `--z-canvas` through `--z-toast` (0, 10, 20, 30, 40), `--icon-stroke: 1.75`, `--icon-size-16`, `--icon-size-20`, `--icon-size-24`. Tailwind's theme table has no z-index namespace.

Exclude `src/app/theme/tokens.css` from Biome's `files.includes`. `app.css` stays formatted. The generator owns the generated bytes.

After `pnpm build`, the emitted CSS contains the background OKLCH and does not contain the literal `@theme`. That is the check that the Vite plugin compiled the imported file. If it does not, keep the generated text in `tokens.css` and change only the import setup until the built file passes that check. Do not hand-write the OKLCH.

### Commands

`package.json`:

- `tokens`: `node tools/tokens/generate.mjs`
- `dev`: `pnpm tokens && vite`
- `build`: `pnpm tokens && vite build`
- `lint`: the current two steps, then `node tools/tokens/generate.mjs --check`

`--check` is read from `process.argv`. Lint calls `node` so CI does not depend on pnpm's argument forwarding. `pnpm tokens --check` is the same script. On success it prints `fresh src/app/theme/tokens.css` and does not write. On failure it prints that the file is stale and to run `pnpm tokens`, then exits 1, and does not write.

The default mode computes the same string. It writes only when the file differs, then prints `wrote src/app/theme/tokens.css`. When the file already matches, it prints the `fresh` line and does not touch mtime. `pnpm dev` and `pnpm build` therefore repair a stale file and then continue. They do not fail on drift. `pnpm lint` does. `pnpm preview` stays `vite preview` and serves `dist/`.

`pnpm check` is unchanged: typecheck, lint, test, build. The token check runs inside lint, which already runs in CI. No workflow edit.

### Tests and the page

`src/core/theme/tokens.test.ts` imports `tokens` and asserts the spec scenarios for the constants, including every hex integer. It does not read the CSS file.

`e2e/theme.spec.ts` uses `e2e/fixtures.ts`. On the production page:

- the `html` background color is `rgb(11, 16, 38)` and the text color is `rgb(230, 234, 245)`
- the heading is Signalfire
- `--zone-accent` for `data-zone` `0` differs from `data-zone` `5`
- `--zone-accent-2` is empty on zone 0 and non-empty on zone 5

`index.html` drops the `base.css` link and sets `data-zone="0"` on `<html>`. Delete `src/base.css`. Leave `App` as the Signalfire heading.

The Node test is written first and failing, then `tokens.ts` is filled. The command scenarios are one green run each. The stale lint run is a temporary edit that is restored in the same task.

## Risks / Trade-offs

- [A `culori` upgrade changes rounded OKLCH] → The lockfile pins it. `pnpm lint` fails until that pull request runs `pnpm tokens`.
- [Tailwind preflight changes the heading's margin and the default sans] → The heading text stays Signalfire. The screenshot shows the color change. The page does not set Inter.
- [`@theme` inside an imported file is skipped by the plugin] → The build check looks for compiled OKLCH and the absence of a literal `@theme`. The page color uses `:root` variables either way.
- [`color-mix` and OKLCH need recent browsers] → Horizontal 03 already limits the game to the latest two desktop versions.
- [Dev rewrites `tokens.css` when constants change] → The write is skipped when bytes match, so a fresh tree does not dirty git.

## Migration Plan

No saved data and no hosting change. The production build still emits a same-origin stylesheet, so `style-src 'self'` stays. Rollback is reverting the change, which restores `src/base.css`.
